Opening a system

  • The start window, Choose a System to Visualize, lists the systems in your library. Click one to open it, or choose Open… (File menu, ⌘O) to find a system's map elsewhere, an application's folder, or a BigBrain file someone sent you (it ends in .bigbrain).
  • A system of your own opens with a seat on this Mac; the demos, and a file someone sent you, open without one. See Your seat.
  • New System… (File menu, ⌘N): choose the application to visualize, usually the client app. Your coding agent reads it and lists what it works with outside its folder: the services it calls, the databases and storage it uses, the programs it runs. For each, choose the folder that holds its code, or leave it out. The window opens as soon as the agent has answered; meanwhile BigBrain looks quickly among the git checkouts beside the project and fills in the folders it recognizes, saying why (for example "provides the routes the app calls"), and lists the projects that call yours, unticked: a service can be mapped on its own, and a caller can be added later or mapped in its own system, which may include this service too. It never changes a folder you chose; Stop ends the search, and unticking "Look among my other checkouts" turns it off for good. Then the map is built from all of them. How long that takes depends on how large and complex the system is; the map opens as soon as it is drawn, and the scenarios and features below are added while you walk it. A large system (over about 120,000 lines written by hand) is built in stages: first an outline of its main parts and subsystems, which opens as soon as it is drawn, then the inside of each subsystem, one at a time, filling in while you look. The progress panel says which stage is under way. If your plan's usage limit is reached, the build waits for it to reset and carries on; if the reset is too far off, or you stop it, the map so far is kept and Continue Building above the map carries on later. Three boxes, all ticked to start with, say what follows the build, one step after another in the agent pane while you look at the map: Developer details (walk through every scenario, then the technical descriptions filled in), Tests (Find the Tests for the whole system) and Features (Catalog Every Feature, last, so it can name the scenarios that show each feature). Each is an agent run of its own and costs what a run costs. Stop This Step skips one; Stop Setting Up ends the rest.
  • Add a Project to This System… (System menu): the services the system uses that have no folder yet and every outside part on the map, including one that appeared after Bring the Map Up to Date found a new service in the code, each with Choose Folder…, and any other folder, such as an open-source library you cloned. The agent maps it and joins it to the parts already there; a snapshot keeps the map as it was.
  • Take a Project Out of This System (System menu, or Settings > Library): its parts become one outside part again, a black box, with the connections and scenario steps that reached it kept, and its comments and To Do's moved to it. No agent is needed, and you can add it back later.
  • The system menu at the top left of the toolbar switches between systems, and does nothing else.
  • The start window offers three demos of the same made-up studio, in the order they happen: 1. Setting up a new system (Play the New System Tour…), 2. Inspecting a system (Open the Demo, also Help > Open the Demo System) and 3. Inspecting a new release (Open the Release Demo). Each is described below.
