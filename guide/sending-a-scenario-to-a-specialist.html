Sending a scenario to a specialist

Someone who has none of your projects, such as a specialist from outside the team, can still inspect a scenario.

  1. Choose File > Send to a Specialist or Export… (⌘E), or, with a scenario selected, Send Scenario to a Specialist… (Scenario menu) or Send to a Specialist… (the step panel's share button, or the scenario's right-click menu in the sidebar). A sheet lists the system's scenarios: tick the ones to send, or All for the whole system. Below them, choose what goes along: the comments and To Do's, the questions and answers (findings among them), the cloud overlays, and the rest of what is known (features, promises, intentions, glossary, screens). The comments and To Do's are a choice of three, each with its count: All of them; Only what is open and what people wrote, which sends the open To Do's, the comments people wrote, and the agent's comments only on a part (or a step or connection) that also has a person's comment or an open To Do, never a folded one or one the agent found no longer true, so the specialist opens to what needs them; or None. The sheet starts at the middle choice once the system has more than twelve of the agent's comments, and at All otherwise. On the command line, bigbrain share --notes open does the same (all, open or none; --with-notes is all). Then Save File… asks where to save it (it ends in .bigbrain). The file always holds the map's parts and connections with their descriptions and the chosen scenarios. It holds no source code, and no folder paths from your Mac. The same file opens in the BigBrain viewer on a headset, so All with everything ticked is how a system is exported for viewing.
  2. Send the file. The specialist double-clicks it, which opens it in BigBrain (or they choose File > Open…, or drag the file onto the window). The system is not in their library, so the file opens to inspect. The first time, BigBrain asks their name and email, filled in from git or their Mac account, so their notes carry it; the banner shows the name with Change…. A banner says "Inspecting a shared scenario" and whose file it is. They walk the scenario, add comments and To Do's, and write questions in the agent pane. The agent is not asked: the questions are saved for you. A stock question button (Security, Data and the rest) saves that stock question with the step, in its area, and a note can be put in an area too (below). The step panel's first step opens with Before you start (see Scenarios). The steps they walk, and Mark Inspected on the step panel, are recorded in the file with their name and the date. Everything is saved into the same file as they go, and they send it back. Save Scenario File As… keeps their notes in a new file instead.
  3. Open the returned file: double-click it, drag it onto the window, choose File > Open…, or Bring In a Specialist's File… in the System menu. The system is in your library, so the file opens as the owner's, whoever exported it: a colleague with the same system in their library is an owner too. A window lists each new or changed To Do and comment to Accept or Reject (for a changed one, Take Their Words or Keep Mine), and each question to Ask the Agent or Dismiss. Nothing goes into your map until you accept it. A question is asked by your agent, as you, with what the specialist was looking at. A question in an area is asked as that stock question, with the specialist's words as the case to answer, and the answer is kept under the stock question like any other. With an inspection open, the steps the specialist walked and the scenarios they marked count in it, under their name, so Coverage and the report include their work; the window lists them under Walked and marked. Bringing the same file in twice counts nothing twice. Inspect It Instead in that window opens the file the way the specialist saw it. A returned file with nothing new for your map opens to inspect straight away, the status line saying so. If you stop part way, a banner in the sidebar brings the window back. Afterwards, System > Specialist Reports opens it again: each accepted To Do and comment has Show, which opens it on the map, and each question asked has Show Answer and, if you kept one, Show Comment. Accepted notes are also in the sidebar's Notes list under the specialist's name; a comment kept from an answer is pinned to the part the answer is about. To keep the list short, Archive a specialist report in its window, or choose Archive All Decided in the menu: an archived report is kept, with your decisions, under Archived, and Unarchive lists it again. Delete… removes it for good; what you accepted stays in your map, but the same file opened again offers its items again.

Several specialists can take turns with one file: each opens it, which opens it to inspect since the system is not in their library, sees the notes and questions of those before them with their names, adds their own and passes it on. Each removes only their own questions. You can bring the file in at any point; what you have already accepted, rejected or dismissed from an earlier copy is not offered again unless someone changed it since.

A team review, with outside specialists

A review can run across a team in which each person has a different reach: outside specialists with the file alone, a team member with the map but not the code, and one with both. The file carries the specialists' work to the team, and the shared map repository carries the team's work between its members. What each person sees is decided by what their Mac holds, so nobody chooses a role: a Mac without the system in its library opens the file to inspect, and a Mac with it opens the file as the owner's.

  1. The owner exports. With the system open, Send to a Specialist or Export… makes the file with the scenarios to review and a password if the specialists should need one. The file records who made it, which tells the specialists who to send it back to; it gives that person no special standing, since anyone with the system in their library is an owner.
  2. The specialists review, one after another, each on their own device. The same file opens in the free BigBrain viewers as well as on a Mac: one specialist reads it on an iPhone Duo, where the viewer puts the map on one half of the folded screen and the notes and the scenario on the other; one on an iPhone, the map and the panel stacked; one on an iPad, side by side; and one on a Vision Pro, the map in the room in front of them. Each viewer plays the scenarios with a voice, and takes comments, To Do's and questions typed or dictated, written back into the same file. The first specialist opens the file, gives a name the first time, walks the scenarios and leaves notes. Each after them opens the same file, sees the notes of those before under their names, and adds their own. The file passes between them by mail or a shared folder, with the password passed another way, and goes back to the team the same way.
  3. A team member with the map decides on the notes. This is often the person closest to the product, with the system in their library but not its code on their Mac. The file opens as the owner's: the map loads and a window lists what the file brings, with the names of both specialists. They accept or reject each comment and To Do. The questions need the code, so they leave them undecided: Done closes the window with the questions still waiting, and a banner in the sidebar, or Specialist Reports, brings it back. Sync System (⌘⇧S) then commits the accepted notes and the specialist report, waiting questions included, to the shared map repository.
  4. A team member with the code asks the agent. They open the system, sync to take the report, and choose Specialist Reports: the report lists the questions still waiting. Ask the Agent on each asks it as them, with what the specialist was looking at as context, and the answer goes into the library's knowledge. They sync again.
  5. The answers reach the team. After a sync, Show Answer in the report opens each answer, for the person who left the questions as for anyone else on the team. To send the answers back to the specialists, export again with the answers ticked, or send what changed since the inspection with Send Changes to a Specialist…; nothing goes back on its own.

Two things keep this tidy. The team syncs before and after deciding, so each decision is made once: what one member has accepted, rejected or dismissed is not offered to the next. And the person with the code works from the synced report, unless a second answer is wanted: bringing the same file in on a second Mac offers its waiting questions again as a second report, and asking them there gives a second agent's answer, on a second checkout of the code, kept beside the first for the team to compare.

Opening a scenario file always asks which you are. Inspect It writes your comments, To Do's and questions into the file. Bring It Into My Map is for the owner: what is new or changed in the file waits for you to accept, and it needs the system's map in your library (the project folders are needed only to ask the agent). Choosing it on a Mac without that map says so and offers to inspect it instead. To check a file before you send it, open it and choose Inspect It.

On the command line, bigbrain share saves the file (--journey a,b or --all, with --with-notes, --with-answers, --with-cloud and --with-everything) and bigbrain bring-in accepts everything in a returned one, and counts the steps walked and scenarios marked in it in the file's inspection, the one named with --review, or the one open.

What the file carries back. Besides the notes, a file's share.json records what the people who walked it added: their questions for you, each with the step it is about and, when they chose one, its area (stockQuestion); the steps each person walked, per scenario, with who and when (walked); and the scenarios each marked Inspected (inspected). These are only ever added to, never rewritten. With the notes goes your library's set of stock questions (questions.json), so a viewer offers the same seven, or your own, with no agent; a file without it offers the standard seven. schema/share.schema.json describes the fields.

Protection. The sheet's last section is a password field, which you may leave blank. With a password the file is encrypted, and the key comes from the password alone, so nothing in BigBrain can open the file without it; Copy puts the password on the clipboard, and you send it another way, such as a text message. Without a password the file is not encrypted: anyone who has it can read it, which is fine for a file that stays on your own machines or goes to someone you trust, and wrong for one that could be intercepted or left on a lost laptop. A file's password is remembered on your Mac, so it opens again without asking; a file without one never asks. Files saved before 29 October 2026 no longer open, since they were locked with a key that lived in the apps themselves; save them again. BigBrain stops opening it after a date you choose: the date is checked against the time on the internet, so a clock set back does not pass, and the latest internet time seen is kept for when there is none. The file is not recalled: whoever has it still has it, and can no longer open it or write into it. Inside, the file is a zip of a system folder with a seal: a file edited or repacked by anything else is refused, with a message saying what changed.
