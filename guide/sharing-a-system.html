Sharing a system

For someone who only reads and comments, send them a file instead (Sending a scenario to a specialist, above): it needs no setup on their side and their notes come back for you to accept. Share a system when a team works on it for weeks, each with the code on their own Mac, and everyone needs the same current map with everyone's work in it. On your own, sharing is also a backup: the project is a copy of the system off your Mac, with its history, and the way to carry it to another Mac of yours.

A system is one folder in your library, <library>/systems/<id>, and sharing it is git: the folder becomes a repository, pushed to one private project on GitHub or GitLab. You make the project and the repository with your own git tools, once. BigBrain's part is small and the same every time: it keeps your Mac's folder paths out of the map and the cloud folder off the server, it counts what is here and not pushed and what others pushed, and Sync System runs commit, pull and push in a Terminal window in front of you. BigBrain holds no login to GitHub or GitLab and never pushes, pulls or clones on its own. A system holds your map, answers, findings and notes, so keep the project private.

Sharing a system of your own

  1. Make a blank, private project on the host, one for this system alone, so you invite people to this one and not to your others. On GitLab: New project, Create blank project, Visibility private, and untick "Initialize repository with a README". On GitHub: New repository, Private, and add no README, .gitignore or license. Copy the project's HTTPS clone address; it ends in .git.
  2. Make the system's folder a repository and give it the address. In Terminal (Settings > Library shows the folder, and the id is its name): 
    cd ~/BigBrain/systems/<id>
git init -b main
git remote add origin <address>

    Commit nothing yet.

  3. Close the system in BigBrain and open it again. Seeing the repository, BigBrain takes your Mac's folder paths out of the map (they stay in Settings > Library), writes a .gitignore that keeps the cloud/ folder off the server, and the sidebar says the changes here are not pushed yet.
  4. System > Sync System… (⇧⌘S). Terminal opens and commits the system. The project has nothing yet, so there is nothing to pull and this first sync pushes straight away; the window says so. If git asks for a login, see below. Reload the project's page: the map's files are there.

From then on, Sync System before and after a session is all there is.

Joining a system someone shared

  1. Get access and the address. The owner adds you to the project (on GitLab as a Developer or above, on GitHub with write access) and tells you the clone address and the system's id, which is the name of its folder in their library.
  2. Clone it into your library's systems folder, under that id. In Terminal (Settings > Library shows where your library is): 
    git clone <address> ~/BigBrain/systems/<id>
  3. Open it in BigBrain. It is in the system menu beside your own, the next time the menu opens. The shared map names no folder on anyone's Mac. If you have the code, the sidebar asks you to choose each project's folder on your Mac, or set them under Project folders in Settings > Library; with the code, the agent can answer and build for you. Without the code you can still read the map, walk the scenarios and leave comments and To Do's.
  4. Sync System sends your comments and takes everyone else's. Who you are in BigBrain is your name and email in Settings > You, not a GitHub or GitLab account, so a team can use either host.

The login git asks for

Git asks in the Terminal window the first time, and your Mac keychain keeps the answer. Username is your GitLab handle or GitHub login, not your email. Password is a personal access token, not the website's password: on GitLab, Preferences, Access tokens, with read_repository and write_repository; on GitHub, a token with Contents read and write, or the repo scope. An SSH key, gh auth login or glab auth login work too, and then git asks nothing.

Day to day

  • The sidebar notice counts what is here and not pushed and, when the server could be asked with the login git has, what others pushed: for example "3 changes here are not pushed yet; 2 changes from others are on the server." Settings > Library shows the same.
  • Check for Library Changes (the two-people button in the toolbar of a shared system; also in the System menu) asks the server once whether others pushed changes to the system's map, comments and To Do's. If they did, a dialog says how many and offers Sync System. It does not look at the projects' code; Check for Code Changes does that. BigBrain does not poll: nothing is asked of the server on its own.
  • System > Sync System… (⇧⌘S) opens Terminal and runs the three steps in front of you: commit what changed here, take everyone else's changes (git pull --rebase), push. When the window is done, BigBrain reads the map again.
  • If two people changed the same note, git stops in that window and names the file; both versions are in it. Fix it and run git add -A && git rebase --continue, then Sync again; or git rebase --abort puts your version back. Nothing is lost.

What is on the server

Everything in the system's folder except cloud/: the map, the scenarios, the answers, the notes, the features, the tests found, the inspections and their reports, the snapshots and the fix requests. The cloud/ folder, the cloud resources chosen on a Mac, stays on that Mac. Each Mac remembers where its own project folders are, and the shared map never names one (Settings > Library lists them and can change them). If BigBrain cannot find a project on this Mac, the sidebar asks you to choose its folder.
